# Godot 2D 游戏开发学习日志

## 一、项目概况

本项目使用 Godot 4 游戏引擎与 GDScript 开发，目标是逐步实现一个具有完整战斗机制的 2D 游戏原型。

开发过程中主要学习 Godot 的场景系统、节点管理、脚本编写、信号机制、碰撞检测以及 UI 交互。

## 二、目前的开发内容

### 1. 游戏场景与节点结构

- 创建 Main 主场景。
- 建立 EnemyContainer，用于统一管理敌人。
- 建立 HUD，用于管理准星和战斗 UI。
- 将敌人拆分为身体、头部、四肢等独立节点。
- 使用独立场景管理敌人，方便后续复用和扩展。

### 2. 敌人系统

实现了敌人的基本属性和状态管理：

- 敌人等级。
- 枪法等级。
- 移动速度等级。
- 普通、轻伤、重伤、死亡四种伤势状态。
- 不同伤势对应不同的角色表情。
- Boss 与普通敌人具有不同的伤害规则。

### 3. 碰撞检测与伤害判定

将敌人的头部和身体设置为独立碰撞区域。

玩家开枪后，通过准星位置进行物理点检测，并根据命中位置判断伤害。

目前实现：
- 头部命中判定。
- 身体命中判定。
- 头部优先判定。
- 不同命中位置对应不同伤害。
- 根据伤势更新敌人状态。

### 4. 敌人波次管理

通过 WaveManager 管理敌人生成和波次推进。

主要学习了：
- 动态实例化场景。
- 将节点添加到场景树。
- 使用信号监听敌人退出场景树。
- 使用 Timer 控制波次间隔。
- 管理当前存活敌人的数组。

### 5. 玩家战斗系统

通过 BattleManager 管理玩家回合。

目前实现：
- 行动力 AP。
- 攻击与闪避行动选择。
- WASD 切换选项。
- Enter 确认行动。
- 行动力耗尽后自动结束行动选择。
- 多次攻击的行动次数管理。

### 6. 闪避判定系统

制作了类似 Undertale 的动态判定条。

判定区域分为绿色、黄色和红色：

- 绿色：成功闪避。
- 黄色：身体受伤。
- 红色：头部受伤。

通过移动判定线的位置决定最终结果，并根据敌人的枪法属性调整判定难度。

同时为连续攻击和 Boss 的特殊判定节奏预留了扩展空间。

### 7. 玩家生命与伤势

实现了玩家三颗心的生命状态显示，并开始完善伤势恢复机制。

## 三、开发过程中遇到的问题

1. **表情图片尺寸不统一**

   不同表情素材的原始尺寸不同，导致切换时人物头部大小发生变化。通过统一显示尺寸和缩放比例解决。

2. **输入事件冲突**

   行动选择和闪避判定都使用 Enter，导致按键被重复处理。通过处理输入事件、标记事件已处理等方式解决。

3. **节点路径错误**

   HUD 和准星节点移动后，原有脚本路径失效。通过检查场景树并修正节点路径解决。

4. **波次切换时计时器报错**

   敌人退出场景树时，游戏可能正在关闭，导致无法正常创建计时器。通过检查节点是否仍在场景树中以及提前保存场景树引用解决。

## 四、阶段性学习总结

通过本阶段的开发，我逐渐熟悉了 Godot 的基本开发流程。

相比单独学习 GDScript 语法，通过实际游戏功能来学习节点、信号、碰撞检测和场景管理，更容易理解这些机制在实际项目中的用途。

目前项目仍处于早期阶段，后续将继续完善战斗逻辑、敌人行为、玩家状态和游戏整体流程。
